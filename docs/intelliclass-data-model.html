IntelliClass AI · backend schema

IntelliClass Data Model

Every table the FastAPI backend creates, with its columns, keys and allowed values. Taken from the SQLAlchemy models and the initial Alembic migration on 15 October 2026.

10 tablesUUID string primary keysUTC timestampsSQLite in development, PostgreSQL + pgvector in production
Privacy rule. No table stores video frames, photos or screenshots. The slides table holds a path to a PNG rendered from the instructor's own PDF, and the events table stores state changes rather than per-second camera features.

    users {
        string id PK "uuid, 36 chars"
        string email UK "indexed"
        string password_hash
        string full_name

        string roll_no UK "nullable, students only"
        datetime created_at
    }
    classes {
        string id PK
        string name
        string course_code
        string instructor_id FK "users.id"
        datetime created_at
    }

        string id PK
        string class_id FK "classes.id"
        string student_id FK "users.id"
        datetime created_at
    }
    slides {
        string id PK
        string class_id FK "classes.id"
        int index "page number, 0-based"
        text text "extracted text for slide matching"
        string image_path "PNG on disk, not in DB"
        datetime created_at
    }
    sessions {
        string id PK
        string class_id FK "classes.id"

        datetime ended_at "nullable"

    events {

        string session_id FK "sessions.id"

Value sets

  • users.role instructor, student, admin.
  • sessions.status live, ended.
  • events.type and alerts.type attentive, sleepy, looking_away, no_face, camera_off, wrong_screen, uncertain, connection_problem. Only sleepy, looking_away, no_face, camera_off and wrong_screen can raise alerts; the rest are shown but never alerted.
  • alerts.severity sleepy 7, no_face 6, wrong_screen 5, looking_away 4, camera_off 3, uncertain 2, connection_problem 1, attentive 0.
  • alerts.status open, then acknowledged when the instructor sends a nudge, then resolved when the student replies "I am back".
  • alert_feedback.response i_am_back, connection_problem.
  • audit_logs.action session.start, session.end, class.enrol, consent.grant, alerts.view, report.view, nudge.send, nudge.reply.i_am_back, nudge.reply.connection_problem.
